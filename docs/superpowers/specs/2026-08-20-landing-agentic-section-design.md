# Секция «Ассистенты — это агенты, а не чат-боты»

Дата: 2026-08-20
Репозиторий: `land_linkeon` (лендинг linkeon.io)

## Задача

Лендинг обещает «принесите задачу — заберите результат», но нигде не объясняет,
чем ассистент Linkeon отличается от обычного чат-бота. Ни одна секция не
упоминает, что ассистенту можно дать файл, что он умеет пользоваться
инструментами и что он возвращает готовые файлы, а не текст.

Донести на лендинге одну мысль: **ассистент не отвечает текстом — он делает
работу**. Принимает любые файлы, работает многошагово, пользуется
инструментами и отдаёт результат файлом.

## Что можно утверждать (проверено по коду)

Ход ассистента исполняется агентом на relay `r.linkeon.io`, который стартует с
`allowedTools = Bash(*), Read(*), Write(*), Edit(*), Glob(*), Grep(*),
WebSearch(*), WebFetch(*)` плюс MCP-инструменты Linkeon
(`spirits_back/relay-agent/server.mjs:385`). Отсюда правдивы утверждения:

- **любые файлы на вход** — `accept="*/*"`, `multiple`
  (`spirits_front/src/components/chat/ChatInterface.tsx:2623`), а не только PDF;
- **файлы на выход** — агент пишет их в свою сессионную папку, платформа сама
  прикрепляет ссылки (`SessionFile`, `resolveEmptyFileLinks` в
  `spirits_back/src/chat/chat.service.ts`);
- **пишет и запускает код** — `Bash`, `Write`, `Edit` разрешены;
- **ищет в интернете** — `WebSearch`, `WebFetch` (учитываются в биллинге как
  отдельные позиции usage);
- **инструменты Linkeon** — `generate_image`, `generate_banner`, `edit_image`,
  `compose_image`, `upscale_image`, `generate_video`, `generate_speech`,
  `read_calendar`, `propose_calendar_event`, `manage_routine`
  (`spirits_back/src/chat/chat-tools.ts`);
- **многошаговость** — один ход это цепочка действий, не один ответ.

## Чего утверждать нельзя

- **«доступ к вашему компьютеру»** — компьютер серверный, в песочнице сессии
  пользователя на стороне Linkeon. Любая формулировка, намекающая на доступ к
  машине или диску пользователя, — ложь.
- **интеграции с CRM, почтой, банком** — их нет.
- **произвольная автоматизация чужих сервисов** — за пределами перечисленных
  инструментов ничего нет.

## Решение

Новая секция `Agentic` + одна правка в Hero. Остальные секции не трогаем.

### Расположение

`src/App.tsx`: между `<Problem />` и `<Assistants />`. Сначала боль («рутина
съедает фокус»), сразу за ней — почему это лечится работой, а не советом, и
только потом знакомство с 16 ассистентами.

### Устройство секции

```
Eyebrow  «Не чат-бот»
H2       «Ассистент не отвечает текстом — он делает работу»
Sub      одно предложение про рабочий стол ассистента

[ Договор ] [ Таблица ] [ Видео ]        ← табы, активный подсвечен

┌─ Вы ───────────────────────────────┐
│ 📎 договор-аренды.pdf              │
│ «Проверь риски и подготовь         │
│  протокол разногласий»             │
└────────────────────────────────────┘
   ● открывает файл — 14 страниц
   ● сверяет условия, ищет практику в сети
   ● находит 4 рискованных пункта
   ● собирает документ с формулировками
┌─ Ассистент ────────────────────────┐
│ ⬇ протокол-разногласий.docx        │
└────────────────────────────────────┘

примечание · CTA «Дать ассистенту задачу»
```

Шаги проявляются существующим `FadeIn` с задержкой по индексу. Первый таб
отрисован по умолчанию, поэтому его текст попадает в пререндер и виден
краулерам; переключение табов — клиентский `useState`.

### Копирайт (RU — источник правды)

**Eyebrow:** Не чат-бот

**H2:** Ассистент не отвечает текстом — он делает работу

**Sub:** Обычный бот умеет только написать в ответ. У ассистента Linkeon есть
свой рабочий стол: он открывает ваши файлы, ищет в интернете, пишет и
запускает код, собирает документ — и возвращает готовый файл.

| Таб | Вход | Шаги | Выход |
|---|---|---|---|
| **Договор** | 📎 `договор-аренды.pdf` — «Проверь риски и подготовь протокол разногласий» | открывает файл — 14 страниц · сверяет условия, ищет практику в сети · находит 4 рискованных пункта · собирает документ с формулировками | 📄 `протокол-разногласий.docx` |
| **Таблица** | 📎 `выписка.xlsx` — «Разнеси расходы по категориям и покажи, куда утекают деньги» | читает 2 300 строк · пишет и запускает код для разбора · группирует по категориям · строит диаграмму | 📊 `расходы-по-категориям.xlsx` + график |
| **Видео** | 📎 `фото-товара.jpg` — «Сделай ролик для Reels» | пишет сценарий · генерирует кадры · собирает видео · добавляет озвучку | 🎬 `reels.mp4` |

**Примечание:** Файлы обрабатываются на стороне Linkeon — ставить на компьютер
ничего не нужно. Работает в тех же токенах, что и диалог.

**CTA:** Дать ассистенту задачу → `appUrl()`

### Правка Hero

Меняется только общий `hero.sub`. Сегментные подзаголовки
(`hero.biz/creator/assistant/video`) остаются как есть — они уже заточены под
рекламные кампании.

- было: «16 AI-ассистентов: пишут контент, разбирают договоры, считают налоги,
  планируют продвижение. Принесите задачу — заберите результат. Первое —
  бесплатно, без карты.»
- стало: «16 AI-ассистентов: читают ваши файлы, ищут, считают и возвращают
  готовые документы, картинки и видео. Принесите задачу — заберите результат.
  Первое — бесплатно, без карты.»

## Реализация

### Файлы

| Файл | Что делаем |
|---|---|
| `src/components/sections/Agentic.tsx` | новый компонент (~130 строк) |
| `src/App.tsx` | импорт + вставка между `Problem` и `Assistants` |
| `src/i18n/locales/ru.json` | ветка `agentic.*` + правка `hero.sub` |
| `src/i18n/locales/{en,es,de,fr,pt,zh}.json` | те же ключи в переводе |
| `tests/smoke.spec.ts` | проверки секции и переключения табов |

Компонент собирается из существующего UI-набора: `Section`, `Eyebrow`,
`FadeIn`, `Button`, иконки `lucide-react`. Новых зависимостей и новых бинарных
ассетов (скриншотов, видео) не добавляется.

### Форма ключей i18n

```json
"agentic": {
  "eyebrow": "...",
  "h2": "...",
  "sub": "...",
  "note": "...",
  "cta": "...",
  "cases": [
    {
      "tab": "Договор",
      "inputLabel": "Вы",
      "outputLabel": "Ассистент",
      "file": "договор-аренды.pdf",
      "ask": "Проверь риски и подготовь протокол разногласий",
      "steps": ["...", "...", "...", "..."],
      "result": "протокол-разногласий.docx"
    }
  ]
}
```

Имена файлов лежат в локали, а не в коде: иначе в китайской версии останутся
русские `договор-аренды.pdf`. Числа внутри шагов («14 страниц», «2 300 строк»)
— часть переводимой строки, отдельных числовых ключей и плюрализации не
заводим: это декоративный пример, а не данные.

### Доступность

Табы — `role="tablist"` / `role="tab"` с `aria-selected` и `aria-controls`,
панель — `role="tabpanel"`. Переключение стрелками ←/→ по активному табу.
Анимация появления шагов уважает `prefers-reduced-motion` (это уже поведение
`FadeIn` — проверить при реализации, при необходимости добавить).

### Проверки

Всё тяжёлое — на тестовой ноде `dv@85.192.61.231` в CI-клоне, не на маке:

1. `pnpm check-locales` — паритет ключей по всем семи локалям, обязан быть
   зелёным;
2. `pnpm typecheck` — `resources.d.ts` типизирует ключи по `ru.json`, опечатка
   в `t()` свалит сборку;
3. `pnpm test:unit` (vitest);
4. `pnpm build` — включает пререндер всех локалей;
5. `pnpm test` (playwright) поверх собранного: секция видна, клик по второму
   табу меняет содержимое панели, текст первого таба присутствует в сыром HTML
   (пререндер не потерял секцию).

Проверку ломаем нарочно: временно убираем ключ из одной локали и убеждаемся,
что `check-locales` краснеет, — иначе зелёный результат ничего не доказывает.

## Открытые вопросы

- **Как катится лендинг.** `deploy.sh` в `spirits_back` катает `spirits_front`,
  а не `land_linkeon`; в README лендинга процедуры нет. Перед выкатом уточнить
  у владельца, чем деплоится linkeon.io, и не изобретать rsync руками.

## Явно вне объёма

- Секция в приложении `my.linkeon.io` (онбординг, пустой чат) — отдельная
  задача, если решим переносить мысль внутрь продукта.
- Скриншоты и видео реального хода ассистента: секция обходится вёрсткой.
- Изменение сегментных hero-подзаголовков и рекламных лендингов `?seg=`.
